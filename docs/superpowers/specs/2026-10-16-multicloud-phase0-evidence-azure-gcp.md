# Phase 0 evidence: Azure and GCP (retrieved 2026-10-16)

Raw evidence behind [the phase 0 findings](2026-10-16-multicloud-phase0-findings.md). Collected by a research agent from official vendor documentation and price lists; rows marked UNVERIFIED have no official source yet.

Method notes. Azure marketing price pages render "$-" without JavaScript, so Azure prices come from Microsoft's public, unauthenticated Retail Prices API (https://prices.azure.com/api/retail/prices, queried with no credentials). GCP network prices were read from raw HTML of cloud.google.com/vpc/network-pricing and /nat/pricing. GCP VM (e2) prices could not be extracted from Google's JS-rendered page: marked UNVERIFIED. All prices USD list/retail, 730 h/month. Retrieved column is 2026-10-16 for every row.

## Summary of surprises (10 lines)

1. Azure default outbound is not "off for all new VNets": only subnets created with the post-2026-03-31 API version default to private; older API versions (including Terraform pinned to older ones) and all existing VNets keep default outbound. Lessons must say "set defaultOutboundAccess=false explicitly".
2. Azure NAT gateway is $0.045/h (about $32.85/mo) plus IP plus $0.045/GB: far more than two Standard public IPs ($7.30/mo). On Azure, "no inbound" is cheapest as public IP + deny-all NSG, not NAT.
3. GCP flips that: Cloud NAT for 2 VMs is about $5.69/mo + data, cheaper than 2 external IPs ($7.30/mo), so private VMs + Cloud NAT is the lower-cost zero-inbound pattern there.
4. An Azure Standard public IP is closed inbound by default (NSG required to open), and the NSG default AllowVNetInBound means VNet-internal traffic is allowed unless you add a deny.
5. GCP "VM free tier" does not cover the external IP ($0.005/h still applies) and only three US regions qualify; e2-micro (1 GB) is below Twingate's 2 GB guidance, Twingate itself suggests e2-small on GCP.
6. Twingate gives no Azure VM size (it points to Container Instances); Azure B1ls is legacy and absent from the current B-family page, so use B2ats_v2 (x86) or B2pts_v2 (Arm, also in the free account).
7. Neither cloud's budget stops spend. Azure: only the free-account/credit spending limit does, by deallocating VMs (and losing VIP settings). GCP: alerts-only never caps; automation via Pub/Sub is delayed and unreliable; spend-cap budgets cover only eligible services.
8. A GCP Gmail learner has no organization, so no folders, no org policy, no hierarchical firewall policies; the org needs Cloud Identity/Workspace. Azure always gives a tenant root management group.
9. GCP firewall: tags and service accounts cannot be mixed in one rule (target side hard-stated); implied-rule priority number is not stated in current docs, so do not teach 65535 as sourced.
10. UNVERIFIED items to recheck: GCP e2 on-demand prices and disk prices, Azure RAM per B-size, Azure East US row for NAT/LB meters, Azure free-account coverage of public IP/disk, GCP 2-step verification and secure-by-default org policies, Spacelift OIDC specifics for both clouds.
