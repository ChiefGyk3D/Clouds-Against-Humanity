Every term the wiki uses, in plain language, with a pointer to the page that explains it properly. Terms a newcomer is likely to meet first are marked **(basics)**; the start-from-zero pages introduce them in order, beginning at [Start here if you are new](Start-Here-If-You-Are-New.md).

| Term | Meaning |
|---|---|
| **3-2-1 rule** | Keep three copies of important data, on two kinds of media, with one copy offsite. A starting point, not a guarantee: it says nothing about whether a copy restores or how old it is. [Backups, recovery and patching: 3-2-1](Backups-Recovery-and-Patching.md#the-3-2-1-rule-and-what-it-leaves-open) |
| **3-2-1-1-0** | Veeam's extension of the 3-2-1 rule: one extra copy that is immutable or offline, and zero errors when the copies are checked and restored. [Backups deep dive: from 3-2-1 to 3-2-1-1-0](Backups-Deep-Dive-3-2-1-1-0-Immutability-and-Restore-Testing.md#from-3-2-1-to-3-2-1-1-0) |
| **AAA** | Authentication, authorization, accounting: who are you, what may you do, and what did you do. Three questions, answered by three kinds of control. [Enterprise identity](Enterprise-Identity-SSO-SAML-OIDC.md#three-questions-authentication-authorization-accounting) |
| **AAAA record** | The DNS record that maps a name to an IPv6 address (the `A` record does that for IPv4); pronounced "quad-A". Publish it last, after the firewall covers IPv6. [IPv6: first, the words](IPv6-Adoption-and-Handling-It-Safely.md#first-the-words) |
| **ABAC** | Attribute-based access control: a decision made from attributes of the person, the resource and the context (department, device state, time) rather than only a role. [Enterprise identity](Enterprise-Identity-SSO-SAML-OIDC.md#groups-roles-and-mapping-people-to-access) |
| **ACL** | Access control list: a list of who may reach what. In Twingate, a signed list of the resources a client (or connector) is allowed to reach. [Twingate: the four pieces](Twingate.md#the-four-pieces) |
| **Account model (blockchain)** | Ethereum's way of keeping score: each account has a balance and a counter of the transactions it has sent (the nonce), as against Bitcoin's unspent outputs. An account can be held by a key or run by contract code. [How Monero works: Ethereum](How-Monero-Works-Compared-with-Bitcoin-and-Ethereum-DeFi-Mixers-Swaps-and-Ransomware.md#ethereum-accounts-contracts-gas-and-what-a-trace-looks-like) |
| **Active Directory (AD DS)** | Microsoft's on-premises directory service: the domain's users, computers and groups, held on domain controllers, with Kerberos and Group Policy built on it. [Windows, AD and macOS](Windows-Active-Directory-and-macOS-in-the-Enterprise.md#first-the-words) |
| **Active provider** | A cloud marked `active: true` in `docs/stages/approved.json`, meaning it is applied right now. The active providers' approved figures must together fit under the current phase's ceiling. [CI, tests and the cost gate](CI-Tests-and-Cost-Gate.md#the-cost-gate) |
| **Adaptor signature** | A signature that is incomplete until a secret value is added, so that completing and publishing it reveals the secret to the other party. It is what lets a Bitcoin-Monero atomic swap work although Monero has no scripts. [How Monero works: why Monero needs adaptor signatures](How-Monero-Works-Compared-with-Bitcoin-and-Ethereum-DeFi-Mixers-Swaps-and-Ransomware.md#why-monero-cannot-use-hash-time-locked-contracts-and-what-is-used-instead) |
| **Address (Bitcoin)** | A label that money can be sent to, made by hashing a public key and adding a version and a checksum. It names no person; whoever holds the matching private key can spend what it receives. [How Bitcoin works: keys, addresses and signatures](How-Bitcoin-Works-Keys-UTXOs-Mining-and-Why-It-Is-Pseudonymous-and-Traceable.md#keys-addresses-and-signatures) |
| **Address reuse** | Using the same address more than once. Everyone who sees one use can follow every other, so it is the simplest link a chain analyst has. [How Bitcoin works: address reuse](How-Bitcoin-Works-Keys-UTXOs-Mining-and-Why-It-Is-Pseudonymous-and-Traceable.md#address-reuse) |
| **Adequacy decision** | A decision by the European Commission under GDPR Article 45 that a non-EU country, territory or sector ensures an adequate level of data protection, so personal data can flow there with no further safeguard. South Africa and China were not on the Commission's list on 2026-11-01. [Privacy law: GDPR transfers](Privacy-Law-Around-the-World-GDPR-PIPEDA-POPIA-and-PIPL-Compared-With-the-United-States.md#transfers-outside-the-eu-adequacy-and-standard-contractual-clauses) |
| **AIDE** | Advanced Intrusion Detection Environment: a free file integrity checker. It builds a database of hashes and attributes from the rules in a config file, then reports what changed. The database and config should live on read-only media or another machine. [File integrity and alerting](File-Integrity-and-Alerting-Tripwire-AIDE-Wazuh.md#aide) |
| **Air gap** | A copy of data that is not reachable from the machine being attacked, such as a drive that is unplugged except while it is written. It protects only while it stays disconnected, and it makes a restore slower. [Backups deep dive: immutable and offline copies](Backups-Deep-Dive-3-2-1-1-0-Immutability-and-Restore-Testing.md#immutable-and-offline-copies) |
| **Alert fatigue** | What happens when a person gets so many alerts, mostly false, that the real one is ignored or closed in a hurry. The cure is fewer, better-tuned alerts, each with a next step. [Logs, SIEM and detection basics: alert fatigue](Logs-SIEM-and-Detection-Basics.md#alert-fatigue) |
| **Allow-list** | A list of the only things permitted (addresses, programs, endpoints); everything else is refused or treated as a lead. The opposite of a blocklist, and more work to keep. [Detecting Tor, I2P and VPN: blocking, allow-listing or watching](Detecting-and-Managing-Tor-I2P-and-VPN-on-a-Network-the-Defenders-View.md#blocking-allow-listing-or-watching-a-policy-choice) |
| **Allowed origins** | In `unattended-upgrades`, the list of repositories automatic updates may come from. A second configuration file adds to the list; it does not replace it unless it starts with `#clear`. [Patch management: configure it](Patch-Management-and-Automatic-Security-Updates.md#configure-it) |
| **ALPR (automated license plate reader)** | A camera plus software that turns images of license plates and vehicles into searchable data with a date, time and place, and compares plates to lists of vehicles of interest. Whether a network of them is a search under the Fourth Amendment is an open question. [US privacy law: license plate readers and Flock](US-Privacy-Law-No-General-Right-the-Patchwork-Data-Brokers-Social-Security-Numbers-and-License-Plate-Readers.md#license-plate-readers-and-flock) |
| **Amateur radio (ham radio)** | A licensed, noncommercial radio service for self-training, experiment and emergency communications. Messages may not be encrypted to hide their meaning, and the station must identify itself. [Radio and off-grid communication: amateur radio](Radio-Off-Grid-Communication-LoRa-Meshtastic-Reticulum-Ham-and-SIGINT.md#amateur-ham-radio) |
| **Amnesic system** | An operating system that starts from the same clean state every time and keeps nothing when it shuts down, such as Tails, which runs from memory and never writes to the hard disk. Its benefit is leaving no trace on a computer you do not control. [The browsing setups compared: Tails](The-Browsing-Setups-Compared-Tor-Browser-Brave-Whonix-Tails-and-Qubes-with-Whonix.md#tails) |
| **AMD Platform Security Processor (PSP)** | A small processor inside AMD CPUs that runs signed, closed firmware before and beside the operating system: boot, a firmware TPM and encrypted virtual machines. Also called the AMD Secure Processor. [Device firmware security: two processors](Device-Firmware-Security-Intel-ME-AMD-PSP-MINIX-and-Kernel-Design.md#two-processors-you-did-not-buy-separately) |
| **anacron** | A program that runs daily, weekly and monthly cron-style jobs after the fact when the machine was off at the scheduled time. A separate, optional package on Debian and Ubuntu. [Cron, timers and init scripts: where cron falls short](Cron-Systemd-Timers-and-Init-Scripts-vs-Systemd.md#where-cron-falls-short) |
| **Anchor (YAML)** | A label (`&name`) on a block of YAML that an alias (`*name`) can paste elsewhere, often with `<<:` to merge it in. Saves typing and makes a file harder to review; this repository's Spacelift config loader refuses them. [Data formats: anchors](Data-Formats-JSON-YAML-HCL.md#anchors-and-the-other-parts-to-be-careful-with) |
| **Ansible** | A command-line configuration management tool: you run it from one control node, it logs in to the machines you list over SSH and makes them match a playbook, with nothing installed on them between runs. [Ansible: what Ansible is](Ansible-Configuration-Management-Versus-Provisioning.md#what-ansible-is) |
| **Ansible Vault** | Ansible's way of encrypting a file or value so it can sit in git; the password is kept elsewhere, and the plain value still exists while a playbook runs. [Ansible: Ansible Vault](Ansible-Configuration-Management-Versus-Provisioning.md#ansible-vault) |
| **ansible-pull** | Ansible turned around: each machine fetches a playbook from a git repository and applies it to itself, so no central machine holds keys to the fleet. [Ansible: ansible-pull](Ansible-Configuration-Management-Versus-Provisioning.md#ansible-pull) |
| **Anonymity** | The state in which an observer cannot tell which individual within a set of others did something (RFC 6973). It is relative to a named observer and to everything that observer knows, so it is a size of crowd, not a switch. [Privacy, security and anonymity: what anonymous means](Privacy-Security-and-Anonymity-Three-Different-Things-and-Why-There-Is-No-Silver-Bullet.md#what-anonymous-means-precisely) |
| **Anonymity set** | The people who look the same to a particular observer. Each attribute you hand out (an account, a cookie, a fingerprint, a writing style, a schedule, a payment) removes people from it; one unique attribute leaves a set of one. [Privacy, security and anonymity: what anonymous means](Privacy-Security-and-Anonymity-Three-Different-Things-and-Why-There-Is-No-Silver-Bullet.md#what-anonymous-means-precisely) |
| **Anonymity-enhanced cryptocurrency (AEC)** | FinCEN's term for a coin built to reduce the transparency of its transactions, such as Monero. FinCEN's ransomware reports note attackers asking for payment in one, sometimes at a discount. [How Monero works: ransomware](How-Monero-Works-Compared-with-Bitcoin-and-Ethereum-DeFi-Mixers-Swaps-and-Ransomware.md#why-ransomware-actors-use-cryptocurrency-and-what-defenders-do-about-it) |
| **Anycast** | One address announced from many locations, so the network sends each client to a nearby one. How a CDN's few addresses serve the world; an address does not name one place. [Behind a CDN](Behind-a-CDN-Real-Client-IPs-and-OSI-Basics.md#anycast-one-address-many-places) |
| **Apache HTTP Server** | A web server, program name `httpd` or `apache2`. Handles many visitors with a chosen multi-processing module (`prefork`, `worker`, `event`) and can read per-folder `.htaccess` files. [LAMP and LEMP from zero: the A and the E](LAMP-and-LEMP-From-Zero.md#the-a-and-the-e-two-ways-to-serve-many-visitors) |
| **Apex (zone apex)** | The bare domain, `example.com`, as opposed to `www.example.com`. It must carry the SOA and NS records, which is why a plain CNAME cannot sit there. [DNS and Cloudflare: records](DNS-Cloudflare-and-Hosting-Your-Own-Website.md#the-records-you-will-meet) |
| **API** (basics) | Application programming interface. Here: the web interface a cloud provider exposes so programs can create and change resources. Everything the web console does is an API call underneath. [What is the cloud](What-Is-the-Cloud.md) |
| **API-driven email security** | Email protection that connects to a mailbox service through its APIs (for Microsoft 365, Microsoft Graph) instead of sitting on the MX path. It can see internal mail, files and chat, and usually acts after delivery unless an inline mode re-routes mail first. It holds broad standing permissions, a new trust boundary. [Email security: the API-driven model](Email-Security-DNS-Gateways-and-API-Driven-Protection.md#model-two-api-driven-cloud-email-security) |
| **API token** (basics) | A long random string that authenticates a program to an API. As powerful as a password, and usually less protected. [Identity, secrets and zero trust](Identity-Secrets-and-Zero-Trust-Basics.md) |
| **Apply** (basics) | The OpenTofu step that carries out a plan and changes real infrastructure. Always preceded by a plan a human has read. [What is infrastructure as code](What-Is-Infrastructure-as-Code.md) |
| **Application service (appservice)** | A Matrix component the homeserver trusts to act for many users. The homeserver pushes events to it over HTTP, so it must be reachable from the homeserver. Bridges are application services. This project runs none; etke.cc hosts the Discord-to-Matrix one. [Roadmap: stage 3](Roadmap.md#stage-3-workloads-planned) |
| **ARES** | Amateur Radio Emergency Service: licensed amateurs who register their skills and equipment with local leaders for public-service communications in a disaster. [Radio and off-grid communication: emergency communications basics](Radio-Off-Grid-Communication-LoRa-Meshtastic-Reticulum-Ham-and-SIGINT.md#emergency-communications-basics) |
| **Argument** | The extra words after a command's name that say what to work on (`ls /tmp`) or how (`-l`). The shell splits a command line on spaces before the program sees it, so quote anything with a space. [The terminal and your first script](Terminal-and-Your-First-Script.md#what-a-terminal-a-shell-a-prompt-and-a-command-are) |
| **ASN** | Autonomous system number: the number of a network that sets its own routing policy and announces address blocks (prefixes) to other networks. An organization can announce the same space through several providers. An ASN names the operator, not the user. [Behind a CDN](Behind-a-CDN-Real-Client-IPs-and-OSI-Basics.md#asns-and-bgp-one-organization-several-roads) |
| **Assertion (SAML)** | The signed XML statement an identity provider sends to an application: who authenticated, when, for which application, with which attributes (such as groups). [Enterprise identity](Enterprise-Identity-SSO-SAML-OIDC.md#saml-step-by-step) |
| **Assume breach** | Designing and operating as if some part of the system will be compromised or fail, and deciding in advance what that costs: contain it, notice it, recover from it. A planning rule, not a prediction. [Plan for failure](Plan-for-Failure-Blast-Radius-and-Assuming-Breach.md#three-ideas-defined-once) |
| **Asymmetric encryption** | Encryption with a key pair: the public key locks, only the private key unlocks. Slow and for small data, so real tools use it to protect a symmetric key. [Hashing, encryption and keys: asymmetric](Hashing-Encryption-and-Keys.md#asymmetric-a-key-pair) |
| **Attestation** | An independent party's written opinion on whether an organization's controls were designed or worked, against stated criteria, for a stated scope and period. A SOC 2 report is one. It is a record of a test, not a law. [GRC: attestations and audit reports](GRC-Governance-Risk-and-Compliance-in-Plain-Terms-Laws-Frameworks-and-Attestations.md#attestations-and-audit-reports) |
| **Atomic swap** | An exchange of coins on two chains between two parties with no trusted middleman, where either both transfers happen or neither does. It does not remove the coins' history before and after. [How Monero works: atomic swaps](How-Monero-Works-Compared-with-Bitcoin-and-Ethereum-DeFi-Mixers-Swaps-and-Ransomware.md#atomic-swaps-exchanging-coins-across-two-chains-with-no-middleman) |
| **ATT&CK** | MITRE ATT&CK, a public catalog of attacker techniques. Used to ask which techniques a set of detection rules does not cover. [Build your own mini SOC: keep tinkering](Build-Your-Own-Mini-SOC.md#keep-tinkering) |
| **Audit evidence** | The records that let someone who was not there verify that a control worked: a merge record, a log line, a ticket, a configuration in version control. Best when the system produces it as a side effect of normal work. [GRC: controls and evidence](GRC-Governance-Risk-and-Compliance-in-Plain-Terms-Laws-Frameworks-and-Attestations.md#controls-and-evidence) |
| **auditd** | The Linux audit system's daemon: it records events the kernel reports (file changes, account changes, commands) to `/var/log/audit/audit.log`. The stage 2 connectors get a short set of watch rules. [Logs, SIEM and detection basics: where logs live](Logs-SIEM-and-Detection-Basics.md#where-logs-live). Its watch form is deprecated; the recommended rule form is in [File integrity and alerting: auditd](File-Integrity-and-Alerting-Tripwire-AIDE-Wazuh.md#auditd-who-did-what). |
| **Attack surface** | Every place an attacker could try to get in or get something out: inbound ports, public addresses, accounts, keys and tokens, dependencies and people with access. You shrink it by removing items, not by hiding them. [Attack surface: list, shrink, measure](Attack-Surface-List-Shrink-Measure.md) |
| **Attack surface map** | The attack surface walked layer by layer. For each layer it records what an attacker could aim at, the control, the test that guards it (or "none") and what to log. [Attack surface map: layer by layer](Attack-Surface-Map-Layer-by-Layer.md) |
| **Authenticated encryption (AEAD)** | Encryption that also checks that the ciphertext was not changed, so a modified message is refused instead of decrypting to something. AES-GCM and ChaCha20-Poly1305 are examples. [Cryptography fundamentals: what encryption is and is not](Cryptography-Fundamentals-Symmetric-Asymmetric-Hashing-Certificates-and-Keys.md#what-encryption-is-and-is-not) |
| **Authentication / authorization** (basics) | Who are you? versus What may you do? Two different questions; a system can get one right and the other wrong. [Identity, secrets and zero trust](Identity-Secrets-and-Zero-Trust-Basics.md) |
| **Authentication-Results** | The header a receiving mail server adds to record what SPF, DKIM and DMARC said about a message (RFC 8601). Trust only the one stamped by your own server; a sender can add a fake one. [Email security: reading headers](Email-Security-DNS-Gateways-and-API-Driven-Protection.md#reading-headers) |
| **Authenticity** | The property that data really came from its stated source. NIST counts it inside integrity; some other frameworks list it apart. [The CIA triad: extra properties](The-CIA-Triad-Confidentiality-Integrity-Availability.md#extra-properties-some-frameworks-add) |
| **Authoritative nameserver** | A server that holds a zone's records and gives the official answer for it, as opposed to a resolver that only looks answers up and caches them. [DNS and Cloudflare: names and who answers](DNS-Cloudflare-and-Hosting-Your-Own-Website.md#names-who-owns-them-and-who-answers) |
| **auto.tfvars** | A value file name (`*.auto.tfvars`) that OpenTofu loads by itself. The repository ignores it like any `*.tfvars`, and the committed example is deliberately not named this way. [Variables, tfvars and secrets](Variables-Tfvars-and-Secrets.md#why-tfvars-is-ignored-and-example-is-committed) |
| **Autodeploy** | A Spacelift stack setting: when on, a plan with no policy warnings applies without a person pressing Confirm. This project leaves it off for every stack. [Spacelift from zero: the pieces](Spacelift-From-Zero.md#the-pieces-in-the-order-you-meet-them) |
| **Automatic updates** | Software that installs updates on a schedule without anyone clicking, such as `unattended-upgrades` or `dnf-automatic`. Installed is not the same as on: check the setting and the timer. [First hour on a new system](First-Hour-on-a-New-System-Updates-and-Baseline.md#what-automatic-updates-means-system-by-system) |
| **Autoscaling** | A loop that reads a metric, compares it with a target and changes how many copies of something run, inside a minimum and a maximum. Without the maximum it is an open-ended bill. [Autoscaling and elasticity](Autoscaling-and-Elasticity-Scale-Out-Targets-Cooldowns-and-Cost-Caps.md#scalable-and-elastic-are-different-words) |
| **Availability** | One of the three security properties: the thing works and authorized people can use it when they need it. Lost to a dead disk, an outage, a flood of traffic, a lost key or ransomware. [The CIA triad: availability](The-CIA-Triad-Confidentiality-Integrity-Availability.md#availability) |
| **Availability zone** | A separate location inside a region, so one building's failure does not take down everything. AWS names one as the region code plus a letter (`us-east-1a`); DigitalOcean speaks of datacenters. [Virtual machines, containers and cloud service models: regions and availability zones](Virtual-Machines-Containers-and-Cloud-Service-Models.md#regions-and-availability-zones) |
| **Backend (state)** | Where OpenTofu keeps its state: a local file by default, or a shared store such as a bucket. Some backends lock the state during writes. [Plans, state, drift and recovery: remote state](Plans-State-Drift-and-Recovery.md#why-teams-use-remote-state) |
| **Backup** | A separate, restorable copy of data made on a schedule and kept where the original's failure does not reach. Not a snapshot on the same disk, and not a replica. A backup you have never restored is a hope. [Backups, recovery and patching](Backups-Recovery-and-Patching.md#four-words-that-sound-alike) |
| **Baseline** | A description of what normal looks like, learned from data, so a deviation can raise an alert; it catches what no one wrote a rule for, and is only as honest as the data it learned from. [Logs, SIEM and detection basics: Exercise 7](Logs-SIEM-and-Detection-Basics.md#exercise-7-a-baseline-instead-of-a-rule) |
| **Baseline (FIM)** | In file integrity monitoring, the stored hashes and attributes of the files you chose to watch, taken while the system is believed clean. A check reports any difference from it, so the baseline is only as trustworthy as the place it is kept. [File integrity and alerting](File-Integrity-and-Alerting-Tripwire-AIDE-Wazuh.md#what-file-integrity-monitoring-is-and-why) |
| **Baseline (system)** | A text record of a machine's package versions, listening ports, users, services, firewall rules and hashes of key files, taken right after the first update, so later changes show up as a diff. [First hour on a new system](First-Hour-on-a-New-System-Updates-and-Baseline.md#exercise-3-take-a-baseline-drift-it-read-the-diff) |
| **Bash** | The most common shell on Linux, also available on macOS and in WSL. The shell this wiki uses for its scripts. [The terminal and your first script](Terminal-and-Your-First-Script.md#pick-your-track) |
| **Bearer token** (basics) | A credential where whoever holds it is let in, sent as `Authorization: Bearer <token>`. The word describes how it is used, not what it is. [APIs and tokens: kinds of credential](APIs-and-Tokens-From-Zero.md#the-kinds-of-credential-side-by-side) |
| **BGP** | Border Gateway Protocol: how networks (ASNs) tell each other which address blocks they can reach, and so how traffic finds its way between providers. [Behind a CDN](Behind-a-CDN-Real-Client-IPs-and-OSI-Basics.md#asns-and-bgp-one-organization-several-roads) |
| **Bicep / ARM template** | Azure's own infrastructure as code: an ARM template is a JSON file that deploys Azure resources, and Bicep is a shorter language that is converted to one. Azure only. [Native IaC versus open standards: Azure ARM templates and Bicep](Native-IaC-vs-Open-Standards-CloudFormation-ARM-Bicep-and-OpenTofu.md#azure-arm-templates-and-bicep-azure-only) |
| **Bind address** | The address a service listens on. A service bound to a private address answers only on that address; bound to the wildcard address (`0.0.0.0` for IPv4) it answers on every address the machine has. [Self-hosting: the worked example](Self-Hosting-When-and-Why-with-SearXNG-as-the-Worked-Example.md#the-worked-example-searxng-as-a-stage-3-workload) |
| **BIP39** | The standard that turns random entropy into a recovery phrase of 12 to 24 words, with a checksum, and the phrase plus an optional passphrase into a seed. Deployed since 2013. [Wallets and key custody: recovery phrases](Wallets-and-Key-Custody-Hot-and-Cold-Hardware-Wallets-Recovery-Shamir-and-Multisig.md#recovery-phrases-bip39) |
| **BIPA (Illinois Biometric Information Privacy Act)** | The Illinois law on collecting and keeping fingerprints, face and iris scans and similar identifiers. It lets people sue, with liquidated damages of $1,000 for a negligent violation and $5,000 for an intentional or reckless one (as the Illinois Supreme Court quoted it in 2019). [US privacy law: biometric laws](US-Privacy-Law-No-General-Right-the-Patchwork-Data-Brokers-Social-Security-Numbers-and-License-Plate-Readers.md#biometric-laws) |
| **Blameless post-mortem** | A short written account of an incident that names contributing causes in the system, process and tools, without blaming a person, so people can report what happened. | **Blast radius** | How far the damage of one failure, mistake or compromise can reach: what is lost or touched when one thing goes wrong. | **Block (blockchain)** | A batch of transactions plus a small header, added to a blockchain as one unit. | **Block header** | In Bitcoin, the 80 bytes that are hashed to make a block's identifier: version, previous block hash, Merkle root, time, difficulty bits and nonce. [Blockchain fundamentals: the block header](Blockchain-Fundamentals-Hashes-Blocks-Nodes-Consensus-and-Forks.md#the-block-header) |
| **Blockchain** | An ordered ledger of blocks kept by many computers, each block carrying the hash of the one before it so any change shows, with rules that make the copies agree. It is tamper evident and tamper resistant, not magic. [Blockchain fundamentals: the idea](Blockchain-Fundamentals-Hashes-Blocks-Nodes-Consensus-and-Forks.md#the-idea-in-one-paragraph) |

[RAID: the price of a small write](RAID-Levels-Parity-Rebuilds-and-Why-RAID-Is-Continuity-Not-a-Backup.md#parity-in-one-xor-and-the-price-of-a-small-write) |
| **X-Forwarded-For** | An HTTP header holding a list of addresses a request passed through, nearest proxy last. Entries added before your first trusted proxy came from somebody else, so read it from the right. Anyone can write it, so a limiter may trust only the values added by its own proxy. [Behind a CDN](Behind-a-CDN-Real-Client-IPs-and-OSI-Basics.md#the-trust-problem); also [Rate limiting: trusting X-Forwarded-For](Rate-Limiting-at-Every-Layer.md#trusting-x-forwarded-for) |
| **XML** | A format that wraps data in matching tags, `<resource name="a"/>`. Strict (every tag must close) and wordy; a parser that follows outside references can be tricked, so configure it not to. [Data formats: TOML, INI, CSV and XML](Data-Formats-JSON-YAML-HCL.md#toml-ini-csv-and-xml-a-paragraph-each) |
| **YAML** | A settings format where indentation is the structure: `name: value` and `- item`. GitHub Actions workflows are YAML. One space can change the meaning. [Data formats: YAML](Data-Formats-JSON-YAML-HCL.md#yaml-indentation-is-the-structure) |
| **Zero trust** (basics) | A design rule: never grant access because of where a request comes from; grant it per request based on who is asking and what for. [Identity basics: zero trust](Identity-Secrets-and-Zero-Trust-Basics.md#zero-trust-with-the-marketing-removed) |
| **Zero-day** | A vulnerability being used against targets before the maker has a patch, or before the maker knew of it. The word is about timing, not severity. [Threats in plain words](Threats-in-Plain-Words.md#zero-day) |

| **ZTNA** | Zero trust network access: per-user, per-resource access decided on every connection, with no implicit trust from network location. Twingate is the ZTNA product here. [Why ZTNA and not a VPN](Why-ZTNA-Not-a-VPN.md#what-ztna-does-instead) |
